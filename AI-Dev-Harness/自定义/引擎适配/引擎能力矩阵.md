## 一、先看这一行：强制力分三档

```
① hooks 强制  >  ② 命令包装强制  >  ③ 仅启动词（靠模型自觉）
   引擎自己的       走 run.bat 启动时        写进 prompt 的规则
   事件机制         前置 自定义\bin           —— 历史实测：弱模型违规 138 次
   模型绕不过       模型执行命令必被计数      ⇒ 只能当兜底，绝不能当机制
```

**一句话**：`hooks` 是唯一「模型不配合也拦得住」的一档；
命令包装是第二档（只要模型要动手，就得过 shell）；启动词是第三档，最弱。

## 三、三条必须记住的结论

### 1. Claude Code 桌面端 = 同一套 hooks，但**生效条件更严**

桌面端与终端读的是**同一个** `.claude\settings.json`（都由 `scaffold-ext.mjs` 落地）。

但 Claude Code 用**会话 cwd** 当项目根、**不向上寻找** `.claude\settings.json`（第 2 批实测）。
所以：

- 在 `我的项目\<项目名>\` **里面**开会话 → hooks 全套生效；
- 在别处（比如用户主目录、harness 根）开会话 → **机制层完全不生效**，只剩命令包装 + 启动词。

`run.bat` 选桌面端时会打印这条，并把启动词写到 `<项目>\.harness\exec-prompt.md`。

### 2. Codex 的 hooks 是「配置合法 ≠ 真会话跑过」

2026-09-12 用 codex **0.153.4** 实测：`config-hooks.toml` 的 `[hooks]` 片段被
`codex --strict-config` **判定为合法配置**（对照组：不存在的键会报 `unknown configuration field`）。

但**没有**跑真实会话验证「hooks 真的被调用」——那要花额度。两件事分开记：

- ✅ 配置格式合法（可复现：`node ../scripts/probe-engines.mjs --engine codex-cli`）；
- ⚠️ 真会话行为未验证（`hook-guard.mjs` 的第一职责仍是协议侦察：把 stdin 落到
  `<harness>\state\codex-probe\stdin.jsonl`，第一次启用后先看这个文件确认字段名）。

### 3. 只有 Claude Code 同时具备「hooks + 输出截断 + 上下文遥测」

Codex / DSH 目前只有命令包装 + 启动词；Trae 只有规则文件 + 启动词。
**不是「这些引擎不行」，而是「它们的机制层还没查明或不存在」**——
能力表里对未知项一律写「未查明」，不写「不支持」。

## 四、怎么复现这张表

```powershell
$H = (Get-Location).Path          # 在 本工作区根目录 下执行本段；路径不写死，换电脑也能用

# 1) 重跑探测（会刷新 引擎能力表.json 的 matrix 段）
node "$H\AI-Dev-Harness\自定义\scripts\probe-engines.mjs"

# 2) 看人读摘要（含「可选用引擎」与「未复验」标注）
node "$H\AI-Dev-Harness\自定义\scripts\probe-engines.mjs" --no-live

# 3) 自检台（含本矩阵与统一解析器的断言）
node "$H\AI-Dev-Harness\自定义\scripts\tests\engine-probe-selftest.mjs"
```

**「本机实测状态」那一列会随机器变**：没装的引擎一律标 skipped，
并把上一轮的实测结论转存到 `lastVerified`（标注来源日期与版本，明确写「未复验」）——
既不说谎，也不因为换机器就把真金白银测出来的结论抹掉。

> ⚠️ **必须在非沙箱环境跑探测**（本轮实测踩到的坑）：受限沙箱里 `%APPDATA%\npm` 可能读不到，
> `dir` 直接报 File Not Found —— 于是**装着的 claude / dsh 会被探成「本机没有」**。
> 那是环境假象。真机（`run.bat` / 你自己的终端）没有这个限制。
