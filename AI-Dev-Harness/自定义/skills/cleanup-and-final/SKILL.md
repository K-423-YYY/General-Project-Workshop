# Cleanup and Final（清单 → 确认 → 执行 → 纯净度自检）

## 适用场景
阶段 4-a / 4-d：项目做完、用户同意结束时的纯净化清理与交付说明。

## 铁律（锁定决策 8 + 前提 5.1）
1. **清理前必须先给清单**：把「将删除 / 将保留」原样告诉用户，等用户明确同意，**不许先斩后奏**。
2. **清理后必须出纯净度自检报告**：项目里不得再有 `.claude\`、`.harness\`、`.trae\`、`AGENTS.md`、`CLAUDE.md`，
   也不得再有 harness 路径引用；报告落盘 `日志\05-清理\`。
3. 只删脚手架与临时文件，**不删项目文件**（代码、`方案.md`、`需求与理念.md`、`.git`、`.gitignore` 一律保留）。
4. 用户没确认前不许宣布完成。

## 执行步骤
1. 问用户：「项目已完成，是否满意？是否同意结束并清理？」
2. 用户同意后，**先跑清单段**（不带 `-Confirm`，它什么都不删）：
   ```powershell
   .\AI-Dev-Harness\内置\scripts\cleanup.ps1 -ProjectRoot "<项目目录>"
   ```
   把打印出来的「将删除 / 将保留」原样转述给用户，等用户明确说「确认清理」。
3. 用户确认后，**再跑执行段**：
   ```powershell
   .\AI-Dev-Harness\内置\scripts\cleanup.ps1 -ProjectRoot "<项目目录>" -Confirm
   ```
   它会：归档 `.harness\` → 删除脚手架 → 撤销项目内 `.claude\` → 写状态 → 跑纯净度自检 → 报告落盘。
4. 自检单独复核（同一实现，可复算）：
   ```powershell
   node .\AI-Dev-Harness\自定义\scripts\purity-check.mjs --project "<项目目录>"
   ```
   期望：`结论：通过`。未通过就按它列出的每一项处理，处理完重跑（脚本幂等）。
5. `git status --short` 确认只剩纯净项目的改动，按需提交「纯净版」。
6. 输出最终说明：项目目录、怎么运行、文档在哪、提交 SHA、下一步（含 GitHub 同步步骤 —— 只告知，不代推）。
7. 请用户确认交付结果。

## 验证方式
- `cleanup.ps1` 退出码 0，且 `purity-check.mjs --project <目录>` 退出码 0（结论「通过」）。
- `日志\05-清理\` 里同时有本次的清单文件与清理报告。
- `git status` 干净或只剩计划内的提交。
- 用户已确认。

## 问题与解决方案
| 问题 | 怎么做 |
|---|---|
| 不确定某文件是否该删 | 一律保留并在清单里列为「将保留」，问用户 |
| 清理后仍有残留 | 看 `日志\05-清理\` 报告里的残留清单，逐个处理后重跑（幂等） |
| 自检发现 harness 路径引用 | 项目文档里残留的引用要改写成相对路径或删掉；不确定的问用户 |
| 用户没确认就去清理 | 违规 —— 立刻停下，把清单补齐再问 |

## 禁止行为
- 禁止在用户确认前执行清理（`cleanup.ps1` 不带 `-Confirm` 时也不会删，别绕开这道闸门）。
- 禁止删除计划内文件、禁止把残留说成"已经干净"。
- 禁止代替用户推送远端（只给步骤与命令）。

## 成功判定
- 清单已给用户、用户已确认、清理已完成、纯净度自检通过、交付说明已输出。
