# Local Verification

## 适用场景
步骤 5：项目骨架搭建完成后的验证；以及开发期每次改动后的验证。

## 必须遵守规则
1. **先分层，再跑测试**（见下表）。跑错层级 = 浪费时间与额度。
2. 跑失败的那一层，修好再往上走；**不许跳层**。
3. 验证通过才能进入下一步。
4. 失败先看 stderr / 日志再改，禁止「猜 → 改 → 重跑」。
5. 验证失败先按模板第一方案处理；处理失败后提示用户并询问。
6. 验证结果**如实记录**，禁止把失败说成通过。

## 验证分层（L1 / L2 / L3）

| 层 | 什么时候跑 | 跑什么 | 耗时量级 | 配额 |
|---|---|---|---|---|
| **L1 定向** | **每次改完一处代码** | 只跑受影响的测试文件（如 `npx vitest run src/a.spec.ts`）+ 改了 .ps1/.sh 时做语法检查 | 秒级 | 不限 |
| **L2 边界** | 一个小功能做完 / 任务边界 | 全量单测 + 类型检查（+ lint） | 分钟级 | 不限 |
| **L3 收尾** | **阶段收尾（4-a/4-d）才跑** | 全量 E2E（playwright / cypress 等） | 十分钟级 | **2 次 / 会话，失败不计数** |

> 「最小验证」的准确定义就是 **L1**。不要把它执行成 L3。

## 禁止矩阵（做了就是违规）

| 禁止 | 为什么 | 正确做法 |
|---|---|---|
| 改一行 → 跑全量 E2E | 上次事故里跑 131 次 / 102 分钟，占 Bash 耗时 45% | 跑 L1 |
| 跳过 L1 直接 L2/L3 | 定位成本成倍上升 | 先 L1 变绿 |
| `sed -i` / `cat >` / python 内联改码 | Windows 下静默失配（退出码 0 但文件没改） | 用 Edit / Write 工具 |
| 把整屏测试日志灌进上下文 | 数万 token 白烧 | 重定向到文件，只读回失败项 + 末尾 |
| 反复重跑同一条失败命令 | 同因同果 | 先读日志，再改，再跑一次 |
| 把未验证内容当作已完成 | 用户无法信任完成度 | 跑 `.claude/hooks/verify-gate.mjs`，引用脚本原始输出 |

## 执行步骤
1. **判定层级**：刚改完一处 → L1；功能做完 → L2；阶段收尾 → L3。
2. **L1**：跑对应测试文件；若改的是脚本，做语法检查。
3. 语法检查：`bash -n 脚本.sh`。
4. PowerShell 脚本语法检查。
5. 编码检查：.ps1 统一 UTF-8 BOM，中文不乱码（缺 BOM 的 .ps1 在 PS 5.1 下会整体解析失败）。
6. 冒烟测试：用假执行器跑通生成、执行、完成、修改等路径。
7. 真实连通测试：用真实 CLI 做最小调用，确认模型、API、网络可用。
8. 运行 selftest 类脚本确认可重复运行。
9. **L3（阶段收尾）**：跑全量 E2E；跑之前先确认本会话配额未超（2 次，失败不计数）。
10. 独立验收：需要「可被引用的证据」时跑 `.claude/hooks/verify-gate.mjs`，让脚本跑、原始输出落盘。

## 验证方式
- 当层测试全部通过（失败项必须逐条列出，不许只报总数）。
- 冒烟测试全部通过。
- 真实连通测试通过。
- 自测通过。
- 命令被机制层拦下时，照拦下的提示换做法，不要换种写法绕过。

## 问题与解决方案
| 问题 | 第一方案 | 备用方案 | 是否需要手动 |
|---|---|---|---|
| 中文乱码 | 统一 UTF-8 BOM | 转换编码 | 否 |
| 语法错误 | 按错误信息修复 | 询问用户 | 否 |
| 真实环境不可用 | 提示用户 | 用户手动验证 | 是 |
| 命中 L3 配额被拦 | 用 `--need-e2e <理由>` 追加，或把 E2E 留到阶段收尾 | 询问用户 | 否 |
| 机制层误拦（正当命令被 deny） | 建 `.harness/bypass` 临时放行，用完删除 | 询问用户 | 否 |

## 禁止行为
- 禁止跳过验证直接进入下一步。
- 禁止忽略失败结果。
- 禁止把未验证内容当作已完成。
- 禁止用更高层级替代低层级（「直接跑全套更保险」是错的）。
- 禁止在未读日志的情况下重跑失败命令。

## 成功判定
- 当层验证全部通过，且失败项（若有）已如实列出。
- 验证记录已输出（必要时落盘到 `.harness/logs/`）。
