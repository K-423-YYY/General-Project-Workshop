# Plan and Requirements

## 适用场景
项目开始阶段，步骤 0-1。

## 必须遵守规则
1. 只读检查，不修改任何文档。
2. 以计划书、需求、理念为准。
3. 发现冲突、缺失、模糊、不可行时，先提示用户，由用户决定。

## 执行步骤
1. 确认计划书、需求文档、理念文档存在。
2. 读取全部文档内容。
3. 列出项目目录结构和当前完成状态。
4. 检查 git 状态、现有代码、现有脚本。
5. 标记模糊点、冲突点、不可行点。
6. 输出项目现状报告和待确认问题清单。

## 验证方式
- 文档已全部读取。
- 项目现状已检查。
- 问题清单已输出。

## 问题与解决方案
| 问题 | 第一方案 | 是否需要手动 |
|---|---|---|
| 文档不存在 | 提示用户提供 | 是 |
| 文档冲突 | 停止并询问用户 | 是 |
| 文档缺失/模糊 | 停止并询问用户 | 是 |
| 方案不可行 | 停止并询问用户 | 是 |

## 禁止行为
- 禁止擅自修改文档。
- 禁止替用户决定方向。
- 禁止忽略文档中的冲突或不可行内容。

## 成功判定
- 已完成只读检查。
- 无未确认的问题遗留。
- 用户已确认可以开始。
