# Skill: SDD 规范驱动生成器 (SpecKite Style)

> 来源：方案 A 的 speckite（A2 核心代码 §3）落地。用于生成/修改计划书。

当收到新功能需求时，请按以下结构生成精简规范文档，**不要直接写代码**：

1. **核心目标**：一句话说明新增功能逻辑。
2. **需求补全**：
   - 目标用户：谁在使用
   - 核心场景：最重要的 1-3 个使用流程
   - 范围外内容：本期明确不做的事情
   - 技术选型：前端、后端、数据库、部署方式
3. **文件变更范围**：列出需要新建/修改的文件路径。
4. **任务分解**：
   | # | 任务 | 优先级(P0/P1) | 状态 |
   |---|------|--------|------|
   | 1 | ... | P0 | [ ] |
   每项任务必须**能在单轮内完成**并有独立验收标准；过大的任务必须拆分为子任务。
5. **验收标准 (Acceptance Criteria)**：
   - [ ] 验收点 1：...
   - [ ] 验收点 2：...
6. **验证方式**：明确运行哪些验证命令（verify / spec-check / e2e）。

待人类输入 "APPROVED" 后，将此规范转交给 Coder 角色执行。
