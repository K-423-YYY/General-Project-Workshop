# Project Workflow

## 适用场景
任何由 AI 辅助完成的项目开发任务。

## 必须遵守规则
1. 优先执行模板中的第一方案。
2. 严格按“项目计划书 + 项目需求 + 项目理念”执行。
3. 不擅自修改目标、范围、交付物、验收标准、技术方向、任务顺序。
4. 不添加计划外内容，不删除计划内内容。
5. 每完成一步做最小验证。
6. 异常先提示用户，由用户决定方向。
7. 办不到或重复几轮仍办不到时，移交用户手动执行，并说明怎么执行。
8. 只有“需要用户手动/决策、任务不可行、任务完成”三种情况才停止。

## 执行步骤
1. 调用 plan-and-requirements：读取并检查计划书、需求、理念，只读检查项目现状。
2. 调用 automation-setup：安装并配置自动化长任务脚本。
3. 调用 task-planning：按计划拆分任务，定义验收标准。
4. 调用 skeleton-building：按计划搭建项目骨架。
5. 调用 local-verification：执行语法、冒烟、连通、自测验证。
6. 调用 task-execution：严格按计划执行主任务。
7. 如遇异常，调用 exception-handling：停止、报告、等待用户决定。
8. 调用 git-delivery：初始化 git、提交、推送、远程验证。
9. 调用 cleanup-and-final：清理临时文件、输出最终说明、用户确认。

## 验证方式
- 每一步完成后检查产出是否存在、是否符合计划书。
- 验证不通过不进入下一步。
- 最终以本地 git 状态、远程仓库、用户确认三项为准。

## 问题与解决方案
| 问题 | 第一方案 | 备用方案 | 是否需要手动 |
|---|---|---|---|
| 网络代理失败 | 清掉 http_proxy/https_proxy/all_proxy 后重试 | 换可用代理/镜像 | 否 |
| CLI 参数变化 | 查看 --version 和 --help 后按当前版本执行 | 提示用户确认 | 否 |
| 子进程无网络/凭据 | 停止脚本，提示用户 | 用户手动执行 | 是 |
| 长任务中断 | session resume --last | 重新创建任务 | 否 |
| 计划不可行 | 停止执行，向用户说明 | 等待用户决定 | 是 |

## 禁止行为
- 禁止擅自修改项目目标、范围、验收标准。
- 禁止绕过计划书自行发挥。
- 禁止隐瞒异常、失败、偏差。
- 禁止在用户未决定前继续执行有争议部分。

## 成功判定
- 所有任务均按计划书完成并通过验证。
- 本地无未提交改动。
- 远程仓库可访问且内容正确。
- 无临时文件残留。
- 交付结果经用户确认。
