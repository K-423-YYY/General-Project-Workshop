# skill-audit（技能体检 / 冲突检测）

## 适用场景
- 用户新增或改动了 `自定义\skills\` 里的某个技能后；
- 每次开工前对技能库做例行体检；
- 用户主动说「检查一下我的技能有没有冲突」。

## 执行步骤
0. **先刷新技能索引**（幂等，1 秒）：
   ```powershell
   node ..\AI-Dev-Harness\自定义\scripts\list-skills.mjs --update
   node ..\AI-Dev-Harness\自定义\scripts\list-skills.mjs --check
   ```
   为什么：新增/改动技能后索引会过期；这一步顺手把索引刷新，避免下次自检报"索引漂移"。
   批量体检时**先看索引**（`list-skills.mjs`，约 2 KB）做初筛，只有冲突嫌疑的技能才通读正文 ——
   不要把 23 个 `SKILL.md` 全量读进来（正文合计约 244 KB）。
1. 扫描 `自定义\skills\` 下所有目录中的 `SKILL.md`，逐个读取其 `name / description / 适用场景 / 规则 / 调用顺序`。
2. 逐一对比，检测四类冲突：
   - 同名 / 近名；
   - 职责或适用场景高度重叠；
   - 规则冲突（一个技能的「必须遵守」与另一个技能的「禁止行为」互相矛盾）；
   - 调用顺序冲突（多个技能都声明自己是第一步 / 总控）。
3. 若无冲突：告诉用户「技能库正常」。
4. 若有冲突：用中文逐条说明冲突点和影响，并给出选项：
   - ① 删除新加入的技能；
   - ② 优化新技能使其兼容（改写其 `SKILL.md`）；
   - ③ 保留两者（说明各自边界）。
   等用户决定后再继续。

## 必须遵守
- 只报告、只给建议，**不擅自删除或修改技能**，除非用户明确同意。
- 检测结论写入 `自定义\skills\冲突记录.md`。

## 成功判定
- 用户已对所有冲突做出决定，且技能库中不再存在未被处理的冲突。
