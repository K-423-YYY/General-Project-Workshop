# 使用说明书（v5.0）

> 配套《终极方案与需求理念（整合版 v5.0）》。本说明书只讲"怎么用"：三步快速开始、详细流程、命令速查、异常处理、作用域、注意事项与 FAQ。

---

## 一、这是什么

**Codex Harness 一键全栈开发引擎**：一个自包含文件夹 `harness/`，复制到你想要开发的项目文件夹里，启动后自动识别当前 AI 软件（Codex CLI / Codex Cloud / DeepSeek Harness），按计划书自动完成"计划 → 开发 → 验证 → 修复 → 记忆 → 提交"的完整闭环。

- 默认**只影响当前项目文件夹**（SCOPE=local）
- 异常时**最多执行 5 轮后停止**并给出状态报告与可行方案
- 需要您手动操作的地方会**停止并提示**，处理完可继续

## 二、三步快速开始

```
第 1 步：拿到 harness/ 整个文件夹
第 2 步：把 harness/ 复制到项目文件夹根目录（没有项目就新建一个空文件夹）
第 3 步：启动：
        Windows：双击 harness\core\run.bat
        或终端：  .\harness\core\run.bat "你的项目目标"
        Linux/macOS：./harness/core/run.sh "你的项目目标"
```

首次启动会自动完成三件事：
1. **自动识别当前 AI 软件**（Codex CLI / Codex Cloud / DeepSeek Harness；未适配会提示且不执行）
2. 检查环境（codex / python / git），缺失时给出中文安装指引
3. 生成本项目的 **SDD 计划书** 到 `项目/docs/plan.md`，然后退出

## 三、详细使用流程

### 3.1 首次运行（生成计划）

1. 运行启动命令（带目标描述）。
2. 自动识别软件 → 生成计划书到 `项目/docs/plan.md` → 退出。
3. **请先查看计划书**：确认任务拆分、优先级、验收标准是否合理；不满意可让 AI 修改。

### 3.2 第二次运行（开始执行）

1. 再次运行同一命令。
2. 引擎按计划书逐轮执行：开发 → 验证（GATE_LEVEL 分层）→ 修复，最多 **5 轮**（MAX_ROUNDS）。
3. 每轮自动：更新 plan.md 勾选 → 更新 ARCHITECTURE.md → 记录 CHECKPOINTS.md → Git 提交。
4. 全部任务完成且验证通过 → 输出 🎉 完成。

### 3.3 修改计划书

```
.\harness\core\run.bat "修改计划：增加用户权限管理模块"
```
含"修改计划 / 编辑计划 / 更新计划"的指令只更新计划书，不写业务代码。

### 3.4 交互菜单（双击 / 无参数运行）

```
=== Codex Harness 一键开发引擎 ===
当前作用域: local（仅影响当前文件夹）[可用 SCOPE=global/off 切换]
1) 生成 / 查看计划书
2) 开始执行（按计划自动开发-验证-修复）
3) 修改计划书
4) 安装为全局命令（SCOPE=global）
5) 关闭影响 / 只读预览（SCOPE=off）
0) 退出
请选择：
```
> 带参数运行时自动跳过菜单（保持非交互，适合脚本/CI 调用）。

## 四、常用命令与开关速查

| 想做什么 | 命令 |
|---|---|
| 一键启动 | `.\harness\core\run.bat "目标"` |
| 修改计划 | `.\harness\core\run.bat "修改计划：增加XX"` |
| 全局安装（任意目录可用） | `SCOPE=global .\harness\core\run.bat`（或菜单选 4） |
| 完全关闭影响（只读预览） | `SCOPE=off .\harness\core\run.bat "目标"` |
| 指定 AI 软件 | `ENGINE=codex-cli` / `ENGINE=codex-cloud` / `ENGINE=deepseek-harness` |
| 调整轮次 / 超时 | `MAX_ROUNDS=10 ROUND_TIMEOUT=20 …` |
| 指定角色执行 | `RUN_AS=planner` / `RUN_AS=tester` / `RUN_AS=coder` |
| 验证层级 | `GATE_LEVEL=0`（仅静态）/ `1`（+SDD 核对，默认）/ `2`（+E2E） |
| 强制计划审批 | `PLAN_APPROVAL=1`（需人工输入 APPROVED 才执行） |
| 装 Firecrawl/Context7（需 Key） | `INSTALL_EXTRA_MCP=1` |
| 关闭自动 git init | `AUTO_GIT_INIT=0` |
| 关闭自动装 MCP | `INSTALL_MCP=0` |
| 同步到 GitHub | `.\harness\sync\sync-to-github.ps1 "更新说明"` |
| 自测 | `.\harness\scripts\selftest.ps1` |

## 五、支持的 AI 软件（自动识别）

| 软件 | 识别方式 | 特点 |
|---|---|---|
| **Codex CLI**（本地客户端） | 存在 `codex` 命令且本地 config.toml 配置模型 | 本地/第三方模型（如 DeepSeek），离线可用 |
| **Codex Cloud**（云端） | `codex login status` 为 Cloud/远程 | 云端模型，无需本地算力/密钥，需网络与订阅 |
| **DeepSeek Harness（DSH）** | 存在 DSH 环境（`$env:DSH_*` / `dsh` 命令 / `~/.dsh`） | 本地运行，模型路由可配，与 DSH 沙箱/审批集成 |
| **其他软件** | — | **未适配，不执行**：会提示支持列表后退出 |

优先级：`ENGINE` 环境变量显式指定 > 自动检测。

## 六、异常情况处理

| 情况 | 引擎行为 | 您该怎么做 |
|---|---|---|
| **死循环 / 卡住 / 无进展** | 最多 5 轮后停止，输出状态报告（已完成/未完成/原因/可行方案）到 `docs/STATUS.md` | 查看报告，按建议①-⑤操作（如拆分计划、调大轮次、检查验证脚本）后重跑 |
| **单轮超时** | 超过 `ROUND_TIMEOUT`（默认 10 分钟）终止本轮 | 慢任务可 `ROUND_TIMEOUT=20` 调大 |
| **需要您手动操作** | 检测到 `NEED_HUMAN` 标记 → 保存进度后停止，输出手动处理指引 | 按指引手动处理（如登录账号、输入验证码），完成后重跑同一命令续接 |
| **验证持续失败** | 到轮次上限后停止，报告失败原因 | 检查 verify/spec-check/e2e 脚本或降级 GATE_LEVEL；复杂报错按《项目使用指南》人工介入微调提示词线索 |
| **软件未适配** | 提示支持列表后退出，不执行 | 安装 Codex CLI/Cloud 或 DSH；或 `ENGINE=…` 显式指定 |

## 七、作用域说明（SCOPE）

| 模式 | 设置 | 影响 |
|---|---|---|
| **local（默认）** | 不设置 | 只影响当前项目文件夹：`docs/plan.md`、`docs/ARCHITECTURE.md`、`docs/CHECKPOINTS.md`、`docs/STATUS.md`、`AGENTS.md`、`.gitignore`、git init/commit 全部在项目内 |
| **global** | `SCOPE=global` | 安装到用户全局：技能与 MCP 注册到 `~/.codex`、注册全局 `harness` 命令（任意目录可调用）；业务状态仍写当前目录 |
| **off** | `SCOPE=off` | 零写入零修改：只输出"将要执行的动作预览"，不装 MCP、不 git init、不写任何文件 |

> 提醒：**不要多项目共用同一个 harness/ 副本**，每个新项目复制一份（指南原要求）；`harness/` 本身保持只读（仅模板），删除它不影响项目文件。

## 九、注意事项与 FAQ

**Q1：第一次运行只生成了计划书就退出了，是坏了吗？**
不是。这是刻意的"人工把关"环节——先看计划、确认验收标准，再二次运行开始执行。

**Q2：换模型/换软件要改脚本吗？**
不用。引擎自动识别当前软件与模型；DeepSeek、官方模型经各自配置即可。

**Q3：token 消耗太高怎么办？**
降低 `MAX_ROUNDS`、`ROUND_TIMEOUT`、`GATE_LEVEL`；大任务先让计划书拆分（AGENTS.md 第 7 条）；验证失败只读错误输出是默认行为。

**Q4：可以中途停止吗？**
可以随时 Ctrl+C。进度已通过 Git 提交保存，重跑同一命令从最近状态继续。

**Q5：AI 会不会改到项目文件夹之外的东西？**
默认不会（SCOPE=local）。所有写入都在项目文件夹内；`harness/` 自身只读。除非你主动 `SCOPE=global` 安装。

**Q6：spec-check 说未通过但我觉得没问题？**
spec-check 是 LLM 核对，可能误判。以 verify 静态命令为准；频繁误报可 `GATE_LEVEL=0` 跳过。

**Q7：Firecrawl / Context7 要装吗？**
可选。需要 API Key（`INSTALL_EXTRA_MCP=1`）；没有 Key 不要开启，不影响主流程。

**Q8：e2e 浏览器测试失败？**
e2e 依赖 Playwright MCP 与浏览器环境。网络受限或环境缺失时降到 `GATE_LEVEL=1` 或 0。

**Q9：必须手动操作的步骤 AI 会硬闯吗？**
不会。检测到需要人工的操作（账号、验证码、审批等）会停止并提示您手动处理，处理完重跑续接。

**Q10：根目录那两份原始文档能改吗？**
`基于 Codex 的一键自动化开发工作流项目计划书.md` 和 `用户需求与自动化项目理念整理.md` 是项目基线，**不要修改**。

## 十、故障排查速查

| 症状 | 处理 |
|---|---|
| 提示"未找到 codex 命令" | 安装并登录 Codex CLI（或使用 DSH 环境） |
| `spawn EPERM` | 设置 `CODEX_BIN` 指向原生 `codex.exe` |
| 子进程只读沙箱 | 配置 `sandbox_mode = "workspace-write"` |
| 推 GitHub `CONNECT tunnel failed` | 清空代理环境变量后再 push（sync 脚本已内置） |
| Codex 参数报错 | 先运行 `codex exec --help` 核对当前版本参数 |
| 计划书生成了但再次运行仍生成 | 检查 `项目/docs/plan.md` 是否存在、是否在项目根目录运行 |
| 验证脚本与项目不匹配 | 编辑 `harness/scripts/verify.*` 按项目调整（只保留前端/后端部分） |
