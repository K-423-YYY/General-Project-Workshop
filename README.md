# General-Project-Workshop（通用项目坊）

一个**可整体复制、可交给任意 AI 的通用项目开发工作区**：把整个文件夹复制到任何电脑，交给 Codex / Claude Code / DeepSeek Harness / Trae 等任意 AI，就能用**中文对话**完成一个完整、纯净的项目。

你不需要写代码、不需要敲命令——只负责用中文说想法、做决定，其余由 AI 完成。

---

## 一、它能做什么

- 用中文对话完成从「想法」到「交付」的完整项目：需求 → 方案 → 文档 → 命名 → 开发 → 验证 → 清理 → GitHub。
- **已经有方案也能接手**：手上已有方案 / 计划文档时，AI 先只读核对（冲突 / 缺失 / 模糊），再归并成项目文档，不从零重问一遍。
- 适配 4 个软件、8 种形态：Codex 客户端；Claude Code 客户端/终端；DeepSeek Harness（客户端/终端）；Trae IDE 国内版/国际版；TraeWork 桌面版；TraeCode CLI。
- 项目完成后自动清理脚手架，只留下纯净的项目文件（代码 + 文档 + git 记录）。
- 所有可改的配置（流程、技能、模板）集中在一个「可改区」，你可以随时修改，不影响内置部分。
- **规则不靠 AI 自觉**：开发期有真实的机制层（hooks 拦危险改码 / 命令包装记账 / 独立验收 / 纯净度自检），换引擎也知道还剩几成强制力。
- **可自检**：11 个自检台 + 完整性检查，随时能验证这套工作区有没有坏、有没有被改乱。

## 二、核心特性

| 特性 | 说明 |
|---|---|
| 中文对话 | 全程中文，不用命令，不限定某一套 AI |
| 即插即用 | 复制文件夹 → 交给 AI → 开工 |
| 通用 | 任意项目类型：网页 / 桌面 / 脚本 / 文档 / 自动化 |
| 纯净交付 | 脚手架开发期存在，完成后自动清除，下次自动再生 |
| 可定制 | 「可改区」（自定义）与「内置区」（适配/脚本）物理隔离 |
| 技能库 | skills 即插即用，并带冲突自动检测 |
| 可复制 | 全相对路径，复制到任何电脑 / 用户名都能用 |
| 无后台 | 不用时不运行任何进程，无定时任务 / 自启 / 文件监听 |
| 机制层 | `.claude\` hooks + `自定义\bin\` 命令包装，改码 / 越权 / 长输出被真的拦住（Claude Code 全套；其它引擎按能力矩阵降级） |
| 日志中心 | 会话 / 命令 / 验证 / 拦截 / 清理 / 引擎 / 审计 / 模型 八类落盘，只追加、fail-open、**日志内容不进 git** |
| 多引擎 | `run.bat` 启动时列出可用引擎、回车沿用上次选择，并打印「本次引擎 + 机制层是否生效」 |

```
├── README.md               ← 本文件
├── .claude\                ← 机制层：hooks + settings.json（开发期生效；不进项目交付物）

├── AI-Dev-Harness\         ← 全部配置所在
│   ├── 开始项目.md          ← 手动粘贴入口（AI 没自动读规则时用）
│   ├── 使用说明.md          ← 一页看懂
│   ├── 自定义\              ← ★可改区：你随便改（但机制层那几项见第九节）
│   │   ├── 对话协议.md     ← 总规则：五阶段流程 + 对话协议 + 纯净 + 技能机制
│   │   ├── 规则源.md        ← 硬规则唯一真源（改完跑 gen-rules.mjs 同步 5 处）
│   │   ├── 模型能力表.json  ← 各模型窗口/能力（env-doctor、自主学习用）
│   │   ├── 引擎能力表.json  ← 各引擎能力矩阵（probe-engines 刷新）
│   │   ├── 流程\            ← 万能项目开发流程模板
│   │   ├── skills\          ← 即插即用技能库（23 个技能）
│   │   ├── templates\       ← 项目文档模板
│   │   ├── 项目规则模板\    ← 生成项目脚手架的规则模板（3 套）
│   │   ├── prompt-模板\     ← 启动词模板（基础 + 硬规则 + 4 个引擎）
│   │   ├── 引擎适配\        ← Codex / Claude / DSH / Trae 的接入层与能力矩阵
│   │   ├── bin\             ← 命令包装层（npm / npx / python / sed … 的记账与拦截）
│   │   └── scripts\         ← 能力层脚本（体检 / 脚手架 / 规则生成 / 审计 / 自检台）
│   ├── 内置\                ← ★内置区：不用改
│   │   ├── adapters\        ← 8 个软件适配说明
│   │   ├── engine\          ← 可选终端入口（run.bat / run.ps1 / run.sh，启动时列引擎）
│   │   ├── scripts\         ← 脚手架 / 清理 / 验证 / 自检脚本
│   │   └── 设计文档\        ← 历史方案归档
│   └── state\               ← 各项目归档 + 引擎选择 + 模型画像（自动维护，不进项目）
├── 项目说明\                ← 项目需求、架构、使用说明（3 份文档）
└── 我的项目\                ← 项目文件夹（做项目时会被改名为项目名；内含骨架 .gitignore，防止你的项目被误提交进本仓库）
```

## 五、快速上手（三步）

1. **拿到它**：`git clone <本仓库地址>`、在 GitHub 上点 **Code → Download ZIP**，或直接把整个文件夹复制到你想做项目的地方 —— 三种效果一样（`日志\` 的 8 个分类目录会在第一次写日志时自动补齐）。
2. **交给 AI**：用 Codex / Claude Code / DeepSeek Harness / Trae 打开这个文件夹；如果 AI 没自动读到规则，就把 `AI-Dev-Harness\开始项目.md` 的内容粘贴进对话框。
3. **中文对话**：AI 会**先跑一次开工体检**，再问你「想做什么项目？」，然后按流程一步步带你完成整个项目。

> 手上已经有方案 / 计划文档？把它放进 `我的项目\` 里，开口说一句
> 「我已经有方案文档，在 xxx，请按它来做，不要再从零设计方案」即可（详见第六节阶段 1）。

## 六、完整使用流程

### 阶段 0 · 开工
AI **先跑开工体检**（`env-doctor`：模型窗口陷阱、hooks 是否注册、上次有没有遗留交接），
再用中文问候、问你「想做什么项目？」，并复述确认你的需求，不急着动手。

### 阶段 1 · 方案沟通与确认
AI 通过一步步对话把项目聊清楚（做什么、主要功能、技术偏好、是否发布等），整理成「方案清单草稿」给你看；你可以反复修改，直到说「确认 / 可以生成方案」。

> **已经有一份方案 / 计划文档？** 把它放进项目文件夹（`我的项目\`）里任意位置，开工时直接说明路径与
> 「按它来做，不要从零设计方案」。AI 会先只读核对（列出冲突 / 缺失 / 模糊点），再把内容归并成项目里的
> `方案.md` 与 `需求与理念.md` —— 详见 `AI-Dev-Harness\自定义\对话协议.md` 第 1–3 章。

### 阶段 2 · 文档生成
确认后，AI 在项目文件夹生成两份文档并永久保留：
- `方案.md`：整个项目的方案（目标、功能、技术方案、实施步骤、验收标准）
- `需求与理念.md`：需求清单与设计理念

### 阶段 3 · 项目命名
AI 推荐 3–5 个名字供你选择，或由你自己起名；确定后把「我的项目」文件夹改名为项目名，并写入两份文档。

### 阶段 4 · 执行与交付
- **开发**：按方案搭建骨架、逐个功能开发，每步最小验证，git 提交进度。
- **结束与清理**：全部完成并验证通过后，AI 先问你「满意吗？是否同意结束？」，同意后**先给你一份「将删除 / 将保留」清单**；
  你确认后才归档工作文件、删除脚手架，并跑**纯净度自检**（脚本出报告，证明项目里没有 harness 痕迹）。
- **同步 GitHub（只告知）**：清理完成后才问你是否同步；AI **只给出可直接复制的步骤与命令**，
  由你自己执行（你明确说「你帮我推」时它才代做）。
- **异常处理**：卡住 / 循环 / 不可行时立即停止，说明原因并给方案，反复「执行 → 停止 → 修改」直到完成。
- **验收与终止**：验收通过并同意停止后，关闭本次开启的所有进程并交付。

## 七、纯净化生命周期

```
开工 → 生成脚手架（按软件最少化）→ 开发 → 完成
   → 出「将删除 / 将保留」清单 → 用户确认 → 归档到 state\ → 删除脚手架
   → 纯净度自检（purity-check.mjs）通过 → 提交纯净版
   → 下次修改：自动恢复 → 重新生成脚手架 → 改完再清
```

## 八、技能机制

- **即插即用**：把含 `SKILL.md` 的文件夹复制进 `自定义\skills\` 即可用，无需登记。
- **冲突检测**：新增技能时自动体检（同名 / 职责重叠 / 规则冲突 / 调用顺序冲突），通过中文对话问你怎么处理：删除 / 优化使其兼容 / 保留两者。

## 九、个性化定制

- 想改流程 → 编辑 `AI-Dev-Harness\自定义\对话协议.md`
- 想加技能 → 复制进 `AI-Dev-Harness\自定义\skills\`
- 想改模板 → `AI-Dev-Harness\自定义\templates\`、`自定义\项目规则模板\`
- 想改硬规则 / 铁律 → 改 `AI-Dev-Harness\自定义\规则源.md`，再跑
  `node AI-Dev-Harness\自定义\scripts\gen-rules.mjs`（自动同步到 8 处：AGENTS.md 第五节、对话协议 §8/§10、
  项目说明 03 第四节、三套项目规则模板、启动词模板；`--check` 可验证同源）

**不要动（框架资产）**：`.claude\`、`自定义\bin\`、`自定义\scripts\`、`自定义\规则源.md`、两个能力表、
`自定义\引擎适配\`、`自定义\prompt-模板\`、`日志\`（只追加）与 `内置\`。
确实要改，先确认「**这是修 harness，不是做项目**」——完整铁律见 `AGENTS.md` 第五节。

## 十、终端模式（可选）

平时推荐用客户端对话框；想用终端自动跑：

```powershell
.\AI-Dev-Harness\内置\engine\run.bat "你的项目目标"
```

详情见 `AI-Dev-Harness\内置\adapters\` 各软件说明。

启动器会先列出可用引擎（**回车沿用上次选择**），并打印「本次引擎 + 机制层是否生效」；选择结果记在
`AI-Dev-Harness\state\engine-choice.json`（本机运行态，不进仓库）。

## 十一、使用前提

- 操作系统：Windows（脚本为 PowerShell）；Linux/macOS 可运行 `run.sh`。
- 至少安装一个支持软件：Codex / Claude Code / DeepSeek Harness / Trae。
- 无需额外配置、无需后台服务。

## 十二、自检与健康检查（怀疑"坏了"时跑）

```powershell
# 1) 结构 + 语义：内置清单（84 项）+ 扩展自检
.\AI-Dev-Harness\内置\scripts\selftest.ps1

# 2) 11 个自检台（hooks / 上下文 / 脚手架 / 探测 / 引擎 / 命令包装 / 自主学习 / 纯净度 / 铁律 …）
node .\AI-Dev-Harness\自定义\scripts\tests\rules-selftest.mjs
node .\AI-Dev-Harness\自定义\scripts\selftest-ext.mjs

# 3) 硬规则是否 5 类消费方同源（改完 规则源.md 后必跑）
node .\AI-Dev-Harness\自定义\scripts\gen-rules.mjs --check

# 4) 交付前/怀疑有残留：纯净度自检（0 = 干净）
node .\AI-Dev-Harness\自定义\scripts\purity-check.mjs --project "<项目目录>"
```

> 提示：自检台要在**非沙箱**环境跑（受限沙箱里读不到 `%APPDATA%\npm`，会把装着的引擎误报成"没装"）。
