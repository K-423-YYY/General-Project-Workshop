# 03 · 使用说明

> 本文档告诉你日常怎么用、怎么改这套工作区。

---

## 一、快速上手（三步）

1. **复制**：把整个文件夹复制到你想做项目的地方（换电脑、换目录、换用户都行）。
2. **交给 AI**：用 Codex / Claude Code / DeepSeek Harness / Trae 打开这个文件夹；
   - 若 AI 没自动读到规则，就把 `AI-Dev-Harness\开始项目.md` 的内容粘贴进对话框。
3. **中文对话**：AI 会先问你「想做什么项目？」，然后按流程带你完成：方案 → 文档 → 命名 → 开发 → 清理 → GitHub。

全程你只需要用中文说话，不用输入任何命令。

---

## 二、各软件怎么用

| 软件 | 做法 |
|---|---|
| Codex 客户端 | 打开本文件夹，直接说「我想做……」，或粘贴 `开始项目.md` |
| Claude Code 客户端 | 打开本文件夹，说「我想做……」，或粘贴 `开始项目.md` |
| Claude Code 终端 | `.\AI-Dev-Harness\内置\engine\run.bat "我想做……"`（启动时会列出可用引擎，回车沿用上次选择） |
| DeepSeek Harness | 对话框粘贴 `开始项目.md` 再描述项目；终端可用 run.bat |
| Trae IDE 国内版/国际版 | 打开本文件夹，右侧对话框粘贴 `开始项目.md` |
| TraeWork 桌面版 | 把工作目录指向 本文件夹，粘贴 `开始项目.md` |
| TraeCode CLI | `.\AI-Dev-Harness\内置\engine\run.bat "我想做……"` |

> ⚠️ Claude Code **桌面端**只有在**项目目录里**开会话才会拿到 `.claude\` 的 hooks（它不向上继承工作区根的配置）；
> 在工作区根开会话时，规则仍然生效，但机制层拦截不生效。详见 `自定义\引擎适配\claude-code\README.md`。

## 三、日常操作

### 3.1 想改流程
编辑 `AI-Dev-Harness\自定义\对话协议.md`。

### 3.2 想加技能
把含 `SKILL.md` 的文件夹复制进 `AI-Dev-Harness\自定义\skills\`。
- 即插即用，无需登记；
- 若有冲突，AI 会中文问你：删除 / 优化 / 保留两者。

### 3.3 想改项目模板
编辑 `AI-Dev-Harness\自定义\templates\`（方案模板、需求与理念模板等）。

### 3.4 想改各软件的规则模板
编辑 `AI-Dev-Harness\自定义\项目规则模板\`（AGENTS / CLAUDE / trae 三套）。

### 3.5 想终端自动跑（可选）
`.\AI-Dev-Harness\内置\engine\run.bat "项目目标"`

### 3.6 自检
- `.\AI-Dev-Harness\内置\scripts\selftest.ps1` —— 检查结构是否完整（清单 + 扩展自检）。
- `node .\AI-Dev-Harness\自定义\scripts\gen-rules.mjs --check` —— 检查硬规则 5 处消费方是否同源。
- `node .\AI-Dev-Harness\自定义\scripts\purity-check.mjs --project "<项目目录>"` —— 纯净度自检（交付前必跑）。

### 3.7 交付前的清理（两段式）
```powershell
# 第一步：只出清单，什么都不删（退出码 3 = 等你确认）
.\AI-Dev-Harness\内置\scripts\cleanup.ps1 -ProjectRoot "<项目目录>"
# 第二步：你确认后执行（归档 → 删脚手架 → 纯净度自检 → 报告落 日志\05-清理\）
.\AI-Dev-Harness\内置\scripts\cleanup.ps1 -ProjectRoot "<项目目录>" -Confirm
```
清单（将删除 / 将保留）与自检报告都会写进 `日志\05-清理\`，事后可查。

## 四、铁律与承诺

> 本节由 `AI-Dev-Harness\自定义\规则源.md` 自动生成（`gen-rules.mjs --check` 可验证 5 处逐字同源），**不要手改**。
> 承诺：**可控** —— 方案、命名、开始执行、清理清单、GitHub、停止，每个关键点都先问你。

<!-- harness:ironrules:begin -->

**一、项目开发期间只动两处**
只能改动：① 项目文件夹（`我的项目\`，阶段 3 起用项目名）；② `AI-Dev-Harness\state\`（归档与运行态）。
其余任何位置一律不动；需要动，先停下来问用户。

**二、机制层属框架资产，不得修改**
`.claude\`、`自定义\bin\`、`自定义\scripts\`、`自定义\规则源.md`、`自定义\模型能力表.json`、
`自定义\引擎能力表.json`、`自定义\引擎适配\`、`自定义\prompt-模板\`、`日志\`
—— 这些是 harness 的机制层（框架资产），项目开发期间**一律不得改动**（`日志\` 只追加，不改写、不提交）。

**三、内置区仍不可动（附例外口径）**
`AI-Dev-Harness\内置\`（`adapters\`、`engine\`、`scripts\`、`设计文档\`）仍是不可动区。
**要改内置区或机制层，先确认：「这是修 harness，不是做项目」** —— 用户明确确认后才动，
并在 `state\` 留一条改动记录（改了哪个文件、为什么、怎么回退）。

**四、交付前必须跑纯净度自检**
跑 `node AI-Dev-Harness\自定义\scripts\purity-check.mjs --project "<项目目录>"`，必须返回 0（结论「通过」）：
项目文件夹里不得残留 `.claude\`、`.harness\`、`.trae\`、`AGENTS.md`、`CLAUDE.md`，也不得有 harness 路径引用。
清理先出「将删除 / 将保留」清单、等用户确认（`cleanup.ps1` 不带 `-Confirm` 时一个文件都不删）。

**五、GitHub 只告知，不代推**
远端同步（建仓库、`git remote add`、`git push`、改可见性）默认**只输出步骤与命令**，由用户自己执行；
只有用户明确说「你帮我推 / 你代做」时才代做，且执行后要把原始输出给用户看。

**六、四条老条款继续有效**
1. 所有路径用**相对路径**，不写死绝对路径（工作区可整体复制到任何电脑、任何目录、任何用户名）。
2. **不使用后台常驻进程**、定时任务、开机自启、文件监听；脚本按需运行，收尾关闭本次开启的所有进程。
3. **全程中文**对话。
4. **用户只说话、不输命令**：一切终端与脚本操作由 AI 自行完成。

> **本铁律更新完即锁定**，之后不再改动；要改，先确认"这是修 harness，不是做项目"。

## 五、常见问题

**Q1：AI 没自动读规则怎么办？**
把 `AI-Dev-Harness\开始项目.md` 内容粘贴进对话框即可。

**Q2：项目做完了，文件夹里还有 AGENTS.md 等文件？**
那是开发期脚手架；完成后 AI 会先给你一份「将删除 / 将保留」清单，你确认后才归档并删除，
删完还会跑一次纯净度自检（脚本出报告，证明项目里没有 harness 痕迹）。

**Q3：下次想改这个项目怎么办？**
重新把 本文件夹（或该项目）交给 AI，它会从 `state\<项目名>\` 恢复上次的计划，自动重新生成脚手架，改完再清。

**Q4：加技能会不会互相打架？**
有 `skill-audit` 自动体检，冲突会问你处理方式。

**Q5：我能动 `内置\` 或机制层吗？**
不建议。你要改的（流程、技能、模板）都在 `自定义\`。
`内置\`、`.claude\`、`自定义\bin\`、`自定义\scripts\`、`规则源.md`、两个能力表、`引擎适配\`、`prompt-模板\` 属**框架资产**，
项目开发期间不要改；确实要改，先确认「**这是修 harness，不是做项目**」。
