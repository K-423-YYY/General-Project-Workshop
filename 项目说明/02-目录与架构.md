# 02 · 目录与架构

> 本文档说明整套工作区的目录结构、每个文件/文件夹的职责，以及整体架构分层。
> **写作口径：与磁盘实际情况一一对应**（2026-09-12 第 4 段逐项核对过；文档里不写磁盘上没有的东西）。

---

## 一、根目录（本文件夹）

```
本文件夹\                        ← 主文件夹：整体复制后交给 AI
├── AGENTS.md               ← 入口规则（Codex / Claude Code 打开即自动读取）
├── README.md               ← 一页看懂 + 目录结构与流程
├── .claude\                ← 机制层：hooks + settings.json（开发期生效，不进交付物）
├── 日志\                   ← 日志中心：8 个分类子目录（只追加、不进 git）
├── 项目说明\               ← 本文件夹（需求理念 / 目录架构 / 使用说明）
├── AI-Dev-Harness\         ← 通用开发配置（全部能力所在）
└── 我的项目\               ← 项目文件夹（做项目时会被改名为项目名）
```

## 三、职责与"能不能改"

| 位置 | 职责 | 项目开发期间能否改 |
|---|---|---|
| `AGENTS.md` | 入口规则（含铁律） | 否（框架资产） |
| `项目说明\` | 三份说明文档 | 否（框架资产） |
| `.claude\` | 机制层 hooks 与状态 | **否**（机制层） |
| `日志\` | 日志中心（只追加） | 只追加，不改写、不提交 |
| `自定义\对话协议.md` | 总规则 | 否（机制层） |
| `自定义\规则源.md` | 硬规则唯一真源 | 否（机制层） |
| `自定义\模型能力表.json`、`引擎能力表.json` | 两个能力表 | 否（机制层，由脚本刷新） |
| `自定义\scripts\`、`自定义\bin\` | 能力层脚本 / 命令包装 | 否（机制层） |
| `自定义\引擎适配\`、`prompt-模板\` | 引擎接入层 / 启动词模板 | 否（机制层） |

## 四、架构分层（六层）

```
[入口层]  AGENTS.md + 开始项目.md + run.bat（选引擎）
              │ 引导 AI 读取规则 / 注入启动词
              ▼
[规则层]  自定义\对话协议.md（总规则） + 规则源.md（硬规则与铁律的唯一真源）
              │ 生成到：3 套项目规则模板 + prompt-模板\硬规则.md + 协议第 10 章
              ▼
[机制层]  .claude\hooks\（拦命令 / 拦工具 / 整形输出 / 注入规则 / 拒停 / 独立验收 / 日志）
              │ 只对 Claude Code 生效；其它引擎靠命令包装 + 启动词（见第八节）
              ▼
[能力层]  自定义\scripts\（体检 / 探测 / 脚手架 / 规则生成 / 审计 / 纯净度自检 / 自检台）
              + 自定义\bin\（npm·npx·sed·perl·python·sleep·playwright 的包装与记账）
              ▼
[执行层]  内置\adapters\（8 形态适配） + 内置\engine\（run.bat/ps1/sh） + 内置\scripts\（脚手架/清理/验证/自检）
              ▼
[项目层]  我的项目\（代码 + 方案.md + 需求与理念.md）  +  state\（归档：harness\、status.json、模型画像）
```

五个区的职责一句话：
- **可改区** `自定义\`：流程、技能、模板随你改；其中的机制层资产（见第三节）不要动。
- **内置区** `内置\`：适配与内部脚本，默认不动。
- **机制层** `.claude\` + `自定义\` 里的脚本/规则/模板：**框架资产**，改它等于修 harness。
- **归档区** `state\`：自动维护，不进项目，保证历史和运行态不丢。
- **日志中心** `日志\`：只追加，便于事后检索；不进 git、不随项目交付。

## 五、8 个软件形态的接入方式

| 软件 | 形态 | 规则自动加载方式 | 机制层强度 |
|---|---|---|---|
| Codex | 客户端 / CLI | 根 `AGENTS.md`（+ 可选 `[hooks]` 段） | 配置级（hooks 需手动合并，见 `引擎适配\codex\`） |
| Claude Code | 客户端（桌面） | `CLAUDE.md` / `AGENTS.md`（**只有在项目目录里开会话才拿到 hooks**） | 全套 hooks |
| Claude Code | 终端 | `CLAUDE.md` / `AGENTS.md` + `run.bat` | 全套 hooks + 命令包装 |
| DeepSeek Harness | 客户端 / 终端 | 粘贴启动词（它不自动读规则文件） | `--patch` 层 + 命令包装 |
| Trae IDE 国内版 | 对话框 | `.trae\rules\project_rules.md` | 仅规则文件（无 hooks） |
| Trae IDE 国际版 | 对话框 | 同上 | 仅规则文件（无 hooks） |
| TraeWork | 桌面 Agent | 规则 + 技能 + 启动词 | 仅规则文件（无 hooks） |
| TraeCode CLI | 终端 | `.trae\rules\` + 技能；走 `run.bat` 时另有命令包装 | 命令包装 + 启动词（CLI 未装则未查明） |

详细矩阵（哪些引擎有 hooks 强制、哪些只有命令包装、哪些只靠启动词）见
`AI-Dev-Harness\自定义\引擎适配\引擎能力矩阵.md`。

## 六、纯净化生命周期架构

```
项目文件夹（开发期）                     state\（归档）
  AGENTS.md / CLAUDE.md \
  .trae\rules\           ├─ 归档 + 删除
  .harness\ 工作文件     │
  .claude\ 机制层       /          →  state\<项目名>\harness\  + status.json
  （保留：代码、方案.md、需求与理念.md、.git、.gitignore）

清理流程（两段式，锁定决策 8）：
  1) cleanup.ps1 -ProjectRoot <项目>          → 出「将删除 / 将保留」清单，落 日志\05-清理\，什么都不删
  2) 用户确认后 .\cleanup.ps1 ... -Confirm     → 归档 → 删除脚手架 → 纯净度自检 → 报告落 日志\05-清理\
  3) purity-check.mjs --project <项目>         → 0=干净 / 1=仍有残留或 harness 引用

下次修改：从 state\<项目名>\ 恢复 → 重新生成脚手架 → 改完再清。
```

## 七、Skills 机制架构

```
用户复制技能文件夹（含 SKILL.md）
        │ 放进 自定义\skills\
        ▼
AI 开工扫描所有 SKILL.md ──► 按需调用
        │
        ▼
skill-audit 体检：同名 / 职责重叠 / 规则冲突 / 顺序冲突
        │
        ├─ 无冲突 → 正常使用
        └─ 有冲突 → 中文询问：① 删除 ② 优化 ③ 保留两者
                      └─ 用户决定后继续，记入 冲突记录.md
```

## 八、日志中心结构（`日志\`，8 个分类）

| 子目录 | 记什么 |
|---|---|
| `01-会话\` | 启动词快照、上下文水位、会话结束摘要 |
| `02-命令\` | 逐条命令：工具、命令、放行/拦截、退出码、耗时 |
| `03-验证\` | 独立验收原始输出（只落盘、不可改写） |
| `04-拦截\` | 每次 deny / warn：规则、命令、替代建议 |
| `05-清理\` | 清理前的「将删除 / 将保留」清单 + 清理后的纯净度自检报告 |
| `06-引擎\` | 引擎探测结果、本次实际引擎、机制层是否生效 |
| `07-审计\` | audit.mjs 会话后审计报告 |
| `08-模型\` | 自主学习轨迹（每次上调/下调的 before→after 与依据） |

规则：只追加不改写、按日期分文件、单文件超 8 MB 轮转；**写入失败不影响主流程**（fail-open 但会在终端出声）。
