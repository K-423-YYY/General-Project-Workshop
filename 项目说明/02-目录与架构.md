```

```

## 四、架构分层（四层）

```
[入口层]  AGENTS.md + 开始项目.md
              │ 引导 AI 读取规则
              ▼
[规则层]  自定义\对话协议.md（总规则） + 自定义\流程\ + 自定义\项目规则模板\
              │ 规定怎么对话、怎么执行、怎么清理
              ▼
[能力层]  自定义\skills\（23 个技能，即插即用）
              │ AI 按需调用
              ▼
[执行层]  内置\adapters\（8 软件适配） + 内置\scripts\ + 内置\engine\
              │ 落地到具体 AI 与具体动作
              ▼
[项目层]  我的项目\（代码）  +  state\（归档）
```

关键隔离：
- **可改区 = `自定义\`**：你优化流程、加技能、改模板都在这里。
- **内置区 = `内置\`**：软件适配与脚本，不用动、也不建议动。
- **归档区 = `state\`**：自动维护，不进项目，保证项目纯净、历史不丢。

## 五、8 个软件适配架构

| 软件 | 形态 | 规则自动加载方式 |
|---|---|---|
| Codex | 客户端对话框 | 根 `AGENTS.md` / 项目 `AGENTS.md` |
| Claude Code | 客户端对话框 | `CLAUDE.md` / `AGENTS.md` |
| Claude Code | 终端 | `claude -p` + `CLAUDE.md`/`AGENTS.md` |
| DeepSeek Harness | 客户端 + 终端 | 粘贴 `开始项目.md`；终端 `dsh --profile headless` |
| Trae IDE 国内版 | 对话框 | `.trae\rules\project_rules.md`（国产模型） |
| Trae IDE 国际版 | 对话框 | `.trae\rules\project_rules.md`（国际模型） |
| TraeWork 桌面版 | Agent 对话 | 规则 + 技能，粘贴 `开始项目.md` |
| TraeCode CLI | 终端 | `.trae\rules\project_rules.md` + 技能/MCP |

所有软件统一遵守 `自定义\对话协议.md`。

## 六、纯净化生命周期架构

```
项目文件夹（开发期）             state\（归档）
  AGENTS.md / CLAUDE.md   ──┐
  .trae\rules\            ──┤ 完成后归档并删除
  .harness\ 工作文件      ──┼──► state\<项目名>\harness\
                          ──┘        status.json
  （保留：代码、方案.md、需求与理念.md、.git、.gitignore）

下次修改：从 state\<项目名>\ 恢复 → 重新生成脚手架 → 改完再清。
```

## 七、Skills 机制架构

```
用户复制技能文件夹（含 SKILL.md）
        │ 放进 自定义\skills\
        ▼
AI 开工扫描所有 SKILL.md ──► 按需调用
        │
        ▼
skill-audit 体检：同名 / 职责重叠 / 规则冲突 / 顺序冲突
        │
        ├─ 无冲突 → 正常使用
        └─ 有冲突 → 中文询问：① 删除 ② 优化 ③ 保留两者
                      └─ 用户决定后继续，记入 冲突记录.md
```
